# 教师使用指南

这份指南面向第一次在教室一体机上使用“角度探险家”的教师。它按“先形成角的概念，再把角度用到路线，最后用答题检查”的顺序组织。每个环节都可以单独使用，不要求一节课完成全部内容。

## 课前准备

### 设备

- 推荐横屏 1920×1080，全屏打开现代版 Chrome 或 Edge。
- 检查浏览器缩放为 100%，关闭会遮挡底部按钮的浏览器侧栏或下载栏。
- 一体机需要可用触控；双人赛最好确认支持两点以上同时触控。
- 若网页可用宽度小于 900 px，双人赛会主动显示“屏幕空间不足”，此时旋转到横屏、退出浏览器分屏或改用全班共答。

### 课前试跑

1. 打开 [在线版](https://misaka16180.github.io/angle-adventure-classroom/) 或离线 HTML。
2. 点击“全屏”，依次打开“角度实验室”和“机器人餐厅”。
3. 在机器人餐厅点“更多 → 教师示例”，选择并载入示例，点“开始运行”后再点“暂停”；用“下一条”观察单步运行。
4. 若准备比赛，进入“角度挑战 → 双人同屏赛”，确认两侧都能点“我准备好了”。不必完成一局，点击“再来一局”即可回到准备界面。

## 建议课堂流程（35—45 分钟）

| 时间 | 教师动作 | 学生活动 | 重点证据 |
| --- | --- | --- | --- |
| 5 分钟 | 角度实验室隐藏度数，拖动活动边提问“哪一个更大” | 用手势或口头估角 | 角的大小看张开程度，不看边长 |
| 8 分钟 | 显示量角器，强调中心、0°刻度线和读数方向 | 轮流切换左右基准边、读内外圈 | 同一个角从不同边开始，读对应的 0°刻度 |
| 15 分钟 | 机器人餐厅先只给“下一条”，让学生预测路线 | 小组说出直行格数、转向角度，拖积木验证 | 90°、180°与方向变化；到终点还要恢复朝向 |
| 5 分钟 | 示范把两个动作放进 C 形循环，再拖出一个动作 | 判断哪些动作重复、哪些只执行一次 | 循环范围由真实容器决定 |
| 8—12 分钟 | 全班共答或双人同屏赛，最后按错题讲评 | 独立作答、解释理由、比较不同路线 | 正确与错误颜色统一，错题成为讲解入口 |

## 环节一：角度实验室

<a href="images/02-angle-lab.png"><img src="images/02-angle-lab.png" alt="角度实验室" width="100%"></a>

*用途：投屏时用来观察活动边、量角器和控制面板的相对位置。点击图片可查看大图。*

1. 先点“隐藏度数”（如果要做估测），请学生说出“锐角、直角、钝角、平角”的判断依据。
2. 让学生按住橙色圆点拖动活动边；绿色射线是基准边，不需要拖动量角器本身。
3. 打开量角器，先问三个动作：量角器中心是否对准顶点？哪条边是 0°？应该读内圈还是外圈？
4. 切换“基准边向左 / 基准边向右”，让学生从对应的 0° 开始读数，比较同一条射线在两圈刻度上的数字。
5. 点顶部度数读数卡“点此输入”，屏内数字盘支持清空、退格和确认；输入范围为 1°—180°。
6. 点击“伸长两条边”演示，把两条边延长后角度不随边长改变；再点“还原边长”恢复。

建议追问：如果把两条边都延长，顶点和开口没有变化，角度为什么仍然相同？如果把 0°刻度线对错，读出的数会发生什么？

## 环节二：机器人餐厅

<a href="images/01-restaurant.png"><img src="images/01-restaurant.png" alt="机器人餐厅" width="100%"></a>

*用途：让学生先看左侧地图上的起点、终点和停靠箭头，再把路线翻译成右侧积木。*

机器人从左下方的“取餐口”出发，朝向右侧的 ① 号桌。完成关卡时，机器人必须回到取餐口并朝右停好。经过当前待送餐桌时自动送餐；如果先经过别的目标桌，地图会保留警告而不提前交付。

### 第一次编程

1. 从左侧积木盒拖出“直行”，接到“程序开始”下方。
2. 点击积木中的数字，使用触屏数字盘输入 1—6 格；转向角度可输入 1°—360°。餐厅只能沿横线或竖线直行，其他转角可用来观察朝向，前进前需转回上、下、左、右方向。
3. 用“下一条”执行一条动作。教师每一步都可以问：“机器人现在在哪个点？朝向哪里？下一步会送哪一桌？”
4. 用“开始运行”连续播放；运行中按钮会变为“暂停”。点当前显示“标准”的速度按钮，可在慢速、标准、快速之间切换。

<a href="images/04-block-loop.png"><img src="images/04-block-loop.png" alt="C形循环" width="100%"></a>

*用途：清楚显示循环的紫色 C 形槽。动作放在槽内才会重复；把动作拖出即可结束重复。*

### 循环的教学说法

把循环当成 Python 的具象化：

```python
move(3)                  # 循环外，先执行一次
for i1 in range(2):
    turn_left(90)        # C 形槽内，重复两次
    move(3)
turn_right(90)           # 循环结束后再执行
```

在界面上，循环是一个完整容器，有开始位置、内部槽和结束位置。拖动循环时，里面的动作一起移动；拖出内部动作时，动作不再重复。最多支持 4 层嵌套，单个循环次数为 1—8 次；最多连接 40 个直行或转向积木，展开后最多执行 128 条动作。空循环会提示补充动作；未接到程序起点的积木只是草稿，不参与运行。

<a href="images/11-python-view.png"><img src="images/11-python-view.png" alt="Python 逻辑预览" width="100%"></a>

*用途：把积木的上下顺序和 C 形槽内的缩进对应到 Python `for` 语句，适合讲清“开始—循环体—结束”的关系。点击图片可查看大图。*

### 反复试错

<a href="images/05-resume-trial.png"><img src="images/05-resume-trial.png" alt="保留现场继续试" width="100%"></a>

*用途：演示学生已经走到某个位置后补写后续积木，为什么不必从头播放。*

- 修改积木不会自动把机器人归零；已经执行且没有改动的前缀会保留。
- 在尾部追加返程动作后，主按钮会显示“接着试”。
- 修改前面的动作或循环时，会回到受影响动作之前重试，避免混用旧结果。
- “退一步”撤回一条已执行动作；“归位”回到取餐口，但都会保留积木。
- “从头验证”适合方案讲清楚以后，请全班完整看一遍。

## 环节三：角度挑战

<a href="images/12-class-quiz.png"><img src="images/12-class-quiz.png" alt="全班共答" width="100%"></a>

*用途：适合教师掌握全班节奏，先让学生说理由，再点选选项并公布答案。*

### 全班共答

全班共答不使用双人赛倒计时。每题可以先让学生举手、比手势或口头说明，再点选答案。提交后正确选项标绿、错误选择标红，并显示正确答案与解析；教师讲完后再点“下一题”。答题结束可点击“再挑战一次”。

### 双人同屏赛

<a href="images/06-duel-ready.png"><img src="images/06-duel-ready.png" alt="双人准备" width="100%"></a>

*用途：两位同学分别站在一体机左右，确认双方准备状态和比赛规则。*

操作顺序：

1. 进入“角度挑战”，点“双人同屏赛”。两名同学分别点击本侧“我准备好了”。
2. 双方都准备后倒数 3 秒。左右题序和选项顺序独立打乱，避免只看对方位置作答。
3. 每题有独立时限，按题目阅读和思考量设置为 15—35 秒；答对 1 分，答错或超时 0 分。
4. 学生选择后立即锁定本题并公示正确答案；约 1.2 秒后自动进入下一题。完成全部题目的一侧会停表等待另一侧。
5. 老师可随时暂停；暂停会冻结倒计时和自动切题。失焦或切走浏览器窗口也会自动暂停。

<a href="images/07-duel-feedback.png"><img src="images/07-duel-feedback.png" alt="逐题反馈" width="100%"></a>

*用途：说明提交后先公示本题结果，再自动进入下一题；绿色和红色含义与左右位置无关。*

比赛中不会在一方尚未完成时提前显示总结果或答案解析。双方全部完成后才出现结果窗口：

<a href="images/08-duel-result.png"><img src="images/08-duel-result.png" alt="比赛结果" width="100%"></a>

*用途：展示得分、答对数、超时数和获胜/并列状态。动画只是短暂鼓励，不阻挡按钮。*

老师点击“查看答案解析”进入讲评：

<a href="images/09-teacher-review.png"><img src="images/09-teacher-review.png" alt="教师讲评" width="100%"></a>

*用途：先看双方选项和答题状态，再按需点“显示答案与讲解”；可筛选只看错题。*

讲评建议：先切“只看错题”，优先讲双方都错的题；询问学生依据，再点击“显示答案与讲解”。绿色只表示答对，红色表示答错或超时，双方都错时两侧都显示红色。

## 学生操作与触控说明

<a href="images/03-touch-keypad.png"><img src="images/03-touch-keypad.png" alt="触屏数字盘" width="100%"></a>

*用途：帮助学生知道数字输入在屏内完成，不要寻找系统键盘。*

- 积木拖入时靠近连接口，看到吸附提示后松手。
- 拖动空白工作区可以平移；在“更多”中点“缩小积木 / 放大积木”调整大小，点“定位开始”找程序起点；工具栏的“放大”用于展开编程区。
- 点选积木后可复制、拆单块或删除；误操作可用撤销/重做。
- 量角器活动边和比赛选项都有较大的触控目标；不要用两根手指同时拖同一个对象。
- 双人比赛两侧可同时点选，但具体多点触控数量由硬件决定。

## 窄屏和布局判断

<a href="images/10-narrow-screen.png"><img src="images/10-narrow-screen.png" alt="窄屏提示" width="100%"></a>

*用途：当浏览器 CSS 可用宽度不足时，提醒教师如何处理，而不是留下空白。*

900 px 只用于双人比赛的并排门槛。角度实验室、机器人餐厅和全班共答仍可在较窄窗口中尝试，但小屏幕会减少地图和积木可见空间。遇到布局拥挤时优先恢复横屏、关闭浏览器侧栏、退出分屏并使用应用内全屏。

## 常见课堂问题

### “机器人送完了，但为什么不算完成？”

检查是否回到取餐口，以及停靠时是否仍朝右。地图上的“停靠朝向 →”就是结束条件；仅仅经过取餐口或送完餐桌还不够。

### “循环为什么没有重复？”

确认动作是否真正放进 C 形槽，循环是否接在程序起点的主链上。游离在工作区旁边的积木只是草稿；空循环会在运行前提示补充动作。

### “比赛结果没有出现？”

必须两侧都完成全部题目；一方还在答题、暂停或尚未超时结束时，结果和解析会保持隐藏。

### “同一个题为什么左右选项位置不同？”

双人赛会分别打乱题序和选项顺序，避免位置记忆。看选项文字和题目内容，不按 A/B/C/D 位置猜答案。

### “颜色看起来像按左右区分吗？”

当前版本固定使用结果语义：绿色 = 答对，红色 = 答错或超时。左右同学使用同一套颜色。

## 下课后的数据

通关标记保存在当前浏览器的本地存储；本次打开期间的积木工作区和临时比赛状态保存在页面内存中。应用不收集姓名，不上传学生答案或成绩。刷新或关闭页面后，未保存的临时比赛和编程现场会重新开始。若学校浏览器禁用本地存储，核心活动仍可操作，但通关标记可能不会保留。
